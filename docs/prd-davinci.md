# PRD — هوفن × دفنشي (استوديو المحتوى داخل نظام هوفن)

> مكتوب 2026-11-04. مبني على: `leen-saz/hoven` (آخر نسخة، ريبو هوفن الفعلي)، وجلسة "نظام ويل لهوفن"، وملف `davinciai-10.3` (Laravel 9، مفكوك ومقروء)، وحزمة `hoven-HOV-6` (القوالب والرادار).
> أي تغيير سلوك يحتاج موافقة لين. ما انقرأ ملف `.env` اللي داخل زب دفنشي.

## 0. قرارات لين (محسومة 2026-11-04)
- **Cloudflare فقط، بدون Laravel.** نأخذ ستركتشر دفنشي ونمطه (موديولات + قوالب + بصمة علامة + حصص استخدام + مستندات) ونبنيه فوق ستاك هوفن الحالي (Astro + Hono + Workers + Supabase). ما ننقل كود دفنشي.
- **هوفن يبقى ريبو منفصل** (`leen-saz/hoven`)، مو شركة داخل منصة وِل.
- سلسلة اعتماد أنس وشاكب **لوِل بس**، وما تنطبق على هوفن.

## 1. الهدف
نظام واحد لفريق هوفن (براندز فور هوم) يسوي المحتوى كله (كوبي، تصميم، صوت، فيديو، سوشال) بنفس شكل دفنشي: مكتبة قوالب، بصمة علامة، مستندات محفوظة، حصص استخدام، وأدوار. وكل إنتاج يمر على سلسلة الاعتماد.

## 2. الاعتماد
يبقى زي ما هو في هوفن اليوم: لين تعتمد كل مرحلة، والنشر في السوشال بعد معتمد مسمّى تختاره المالكة (migration 017). الامتثال تنبيه مو قفل. ما نضيف سلسلة جديدة.

## 3. الوضع الحالي لهوفن (الموجود)
| الجزء | الحالة |
|---|---|
| الأساس: Astro + Hono + Workers + R2 + Supabase `hoven-ads`، دخول بإيميل، أدوار، سجل `audit_log`، عزل بالشركة `scoped()` | شغال على staging |
| 12 موديول بحالة `live`: ملخص الأداء، الرصد، التصميم، الكوبي رايتر، الصوت، السوشال، المحتوى و SEO، الرحلات، الامتثال، المدير (Maestro)، المعرفة، التتبع | شغال |
| بيانات: Meta وSnap وGoogle وسلة، تاريخ من 2023-08-29، سحب كل ساعة | شغال |
| المعرفة: صوت العلامة، الادعاءات، الممنوع، شات تدريب 12 سؤال، الشعار والألوان والخطوط (`brand_assets`) | شغال |
| التصميم: بريف من أفضل الإعلانات، معاينة canvas، النص طبقة فوق الصورة بخط ثمانية، نصوص من Workers AI | شغال |
| مزامنة وِل التلقائية (PR كل ساعة) وCI | شغال |
| التحويل (المرحلة 6) | جاهز، ينتظر "انشر الإنتاج" |

**معلّق على لين:** سرّا `HOVEN_SUPABASE_URL` و`HOVEN_SUPABASE_SERVICE_ROLE_KEY` في GitHub (بدونهم خطوة التصدير تفشل وما فيه أرقام في اللوحة)، الشعار الأصلي، خيار "Allow GitHub Actions to create PRs"، حذف الفروع القديمة، حذف مشروع Supabase `hoven` الخامل.

**شغل هوفن اللي برا الريبو (ما انتقل للنظام):**
- `hoven-studio`: 24 قالب HTML (8 أنواع × 3 مقاسات)، `render.py`، فحص ورقة المصدر `check-source.py`، دفعة B001. للمراجعة، مو للنشر.
- `hoven-agents`: رادار الترند (نتيجته رفض الدفعة لعدم وجود مرجع أصلي)، دليل اللهجة السعودية، المراجع.
- سكيل التصميم `HOVEN-MASTER-SKILL.md`: **مسودة، ما اعتمدتها لين.**
- موقع الجملة `hoven-preview` (Next.js): منفصل، يبقى منفصل.
- `hoven-content-bot` (مذكور في السكيل): غير موجود على هالجهاز، يحتاج تأكيد وين هو.

## 4. ستركتشر دفنشي (من الملف، مو من الذاكرة)
- Laravel 9، PHP 8.0.2+، 134 موديل، ثيم Blade `default` فيه `admin` و`user` و`frontend` و`auth`.
- كنترولرات: `Admin` (إعدادات، مستخدمين، CMS، سوق الإضافات، ثيمات)، `User`، `Api/V1` و`V2`.
- أدوار Spatie: admin، user، subscriber. فحص اشتراك، 2FA، لغات (فيه `ar.json`).
- نظام إضافات: موديل `Extension` + تثبيت/إلغاء حزم + ترخيص مفتاح.
- وحدات المستخدم: قوالب (+ قوالب مخصصة ومفضلة)، شات (+ بروبمتات وملفات وويب)، صور (+ ai_photoshoot)، تحويل نص لصوت (+ عزل صوت)، تفريغ صوت، إعادة صياغة، محرر ذكي، ويزرد مقالات، بصمة علامة، مستندات ومجلدات (workbook)، RSS، يوتيوب، تكاملات، فريق، دعم.
- بنية الخدمات: `AIService`، وخدمات TTS منفصلة لكل مزوّد، و`Jobs` للطابور، وبوابات دفع كثيرة.

## 5. الخريطة: دفنشي ← هوفن
| دفنشي | عند هوفن اليوم | الحالة | الشغل |
|---|---|---|---|
| قوالب (Templates) | الكوبي رايتر (live)، وقوالب `hoven-studio` برا الريبو | جزئي | مكتبة قوالب في قاعدة البيانات: فئة، لغة، مفضلة، لكل شركة. استيراد قوالب HOV-6 |
| بصمة العلامة (Brand Voice) | المعرفة + `brand_assets` | موجود | ربط سكيل هوفن (بعد اعتماده) كبنود معرفة، وتطبيقها على كل القوالب |
| الصور / ai_photoshoot | التصميم (Workers AI + canvas) | جزئي | استوديو منتج: صورة سلة المرجع + مشهد جديد، والنص دايماً طبقة فوق |
| صوت (TTS) | الصوت (live، مجاني) | موجود | تحميل ملف الصوت، أصوات جاهزة |
| شات / مساعد | Maestro (Paperclip) | جزئي | يتوقف على المرحلة 9 (Containers + Workers Paid) |
| محرر ذكي / إعادة صياغة / ويزرد المقالات | المحتوى و SEO | جزئي | محرر واحد بتاريخ نسخ، يمر على الامتثال |
| مستندات / Workbook | ما فيه | **ناقص** | جدول `documents` ومجلدات: كل ناتج (نص، صورة، صوت) ينحفظ بحالة اعتماد |
| RSS / ترند | الرصد | جزئي | رادار هوفن كمصدر في الرصد، وبوابة ورقة المصدر (5 حقول، ≤14 يوم) كقاعدة |
| فريق وأدوار | مستويات وصول (014) + شركات (006) | موجود | يبقى كما هو |
| اشتراكات / رصيد / بوابات دفع | ما فيه | **ناقص** | **سجل استخدام وحصص** لكل شركة (نصوص، صور، ثواني صوت). بدون بوابات دفع في هالمرحلة |
| API V1 | ما فيه | ناقص | مؤجل، بعد التحويل |
| 2FA | ما فيه | **ناقص** | مطلوب قبل ما تنفتح الحسابات لفريق أكبر |
| إضافات / سوق | سجل الموديولات + قفل لكل شركة (013) | موجود | هو نفس الفكرة، يبقى |
| الدعم / الإشعارات / CMS / مدونة / تثبيت / ترخيص | — | خارج النطاق | داخلي، ما نحتاجه |
| Code / Vision / يوتيوب | — | خارج النطاق | ما له علاقة بمحتوى هوفن |

## 6. اللي باقي (مرتب)
1. **مكتبة القوالب + المستندات** (الناقص الأكبر من دفنشي).
2. **سجل الاستخدام والحصص** لكل شركة.
3. **نقل شغل HOV-6**: القوالب، فحص ورقة المصدر، الرادار، دليل اللهجة، مع بقاء كل شي "للمراجعة" لين تعتمده.
4. **استوديو المنتج** (صورة سلة + مشهد جديد) على Workers AI المجاني.
5. **نشر سلة** (وصف المنتج المعتمد) بموافقة، عبر ربط سلة الموجود.
6. **2FA**.
7. المرحلة 6 (التحويل) والمرحلة 7 (التشديد) تبقى كما هي في `docs/plan.md`.

## 7. المراحل الجديدة (كل واحدة PR مستقل بعد "ادمج")
| المرحلة | الشغل | يخلص لما |
|---|---|---|
| A. القوالب والمستندات | جداول `templates` و`documents` و`folders`، صفحات، مفضلة | قالب HOV-6 يشتغل من الواجهة وينحفظ ناتجه |
| B. الاستخدام | جدول `usage_ledger`، حصص، شريط استخدام | تجاوز الحصة يرجع رسالة، والأرقام تطابق الاستهلاك |
| C. نقل HOV-6 | القوالب، فحص المصدر، الرادار، دليل اللهجة | نفس مخرجات `render.py` من داخل النظام |
| D. الاستوديو | صورة المنتج + طبقة النص | دفعة B001 من الواجهة للمراجعة |
| E. الأمان | 2FA | الدخول بكود ثاني |

قواعد ثابتة تمشي على الكل: ما يطلع كود إعلان للعميل، النص طبقة فوق الصورة دايماً، ما فيه أرقام أو ادعاءات أو أسعار مخترعة (placeholder)، الامتثال تنبيه مو قفل، مجاني أو مستضاف عندنا فقط، وحسابات الإعلانات قراءة بس.
